# Implementation Research: k5-work (open-source Cowork clone)

## The Task
Web app, TypeScript full-stack, thin-slice MVP of all four pillars:
1. Computer Use (sandboxed desktop), 2. Browser Use, 3. Office docs (xlsx/pptx/docx), 4. Company integrations (Slack/Notion/Linear/Jira).
Model layer via ACP (Agent Client Protocol) bindings to open-source harnesses (e.g. `opencode acp`, Goose, Gemini CLI, Codex).
Stack versions: Node 26, TypeScript 5.6, React + Vite frontend, Express + WS backend. No code until sign-off.

## 1. Common Gotchas
- **ACP is editor-protocol, not agent-loop.** ACP standardizes client<->agent JSON-RPC over stdio (`initialize`, `session/new`, `session/prompt`, permission prompts, tool calls) — source: agentclientprotocol/agent-client-protocol README, Zed ACP blog 2025-08-27. Gotcha: the SDK only handles wire protocol; reasoning loop, compaction, permission UI are yours. If you spawn `opencode acp` you inherit its loop, but then k5-work is a thin client and you lose control of computer/browser tools unless the harness exposes them via MCP.
- **Browser-use: accessibility-tree gaps + silent wrong-success.** Browser-Use perceives via pruned DOM/AX tree, not screenshots (4x cheaper than vision-only) — source: aiworkflowlab.dev 2026-05-05, use-apify guide 2026-03-08. Gotcha: cookie banners / shadow-DOM buttons missing from tree means model never sees them; agent can hallucinate plausible data with no error. Must require evidence-based asserts (exact strings, URLs), `max_steps` budget, domain allowlist.
- **Browser-Use left Playwright (v0.6.0, Aug 2025).** Now drives Chromium directly over CDP with typed bindings (cdp-use) citing Node-relay latency, state drift, 16k-px screenshot crashes — source: lite.ego.app 2026-08-09, browser-use.com bitter-lesson 2026-09-15. Gotcha: if you build on Playwright you re-inherit the latency/drift they removed. Recommendation in their own posts: reuse a proven harness (Pi, Codex, OpenCode) + expose a simple browser tool, let model choose observations.
- **Computer Use must be disposable VM-per-task.** Anthropic reference (claude-quickstarts/computer-use-demo) runs Linux desktop in Docker with X11+VNC, single-session, must reset between sessions. Anthropic containment post (2026-05-25): Cowork runs full VM (Apple Virtualization/HCS), workspace-only mounts, credentials never enter guest, symlink resolution before path validation, MITM proxy for API keys. Gotcha: mounting host creds as env vars leaks via process listing; use short-lived JWT via vsock, block RFC1918/link-local/IMDS (169.254.169.254) at host nftables.
- **Office: pptxgenjs silent corruption.** Mutates option objects in-place (never reuse), combo charts + secondary axes trigger repair dialogs (fixed v4.0.1 but still fragile), uppercase image paths break OOXML rels, old versions break "Edit Data in Excel" — source: dev.to/jakexkim 2026-06-22, PptxGenJS #860/#1013. `docx` lib is write-only (no edit existing), ExcelJS has no auto-fit columns and weak chart support — source: davide-travaglini/node-red-contrib-officedocs. Must test output on Windows PowerPoint, not just LibreOffice/macOS.
- **Notion: share-gating + 3 req/s global.** Integration can't access pages not explicitly shared — #1 stuck point. Rate limit 3 r/s per integration globally; background sync starves interactive paths. Data Sources API (Aug 2025) changed data model (database != table). Webhooks fire on property changes, not body edits — still need polling with watermark backstep (60s) for eventual consistency — source: youngju.dev 2026-05-14, codecanis.com 2026-04-15.
- **Slack: webhook bound to one channel; bot must be invited.** `not_in_channel` if not invited. Bolt 4 + Socket Mode easiest for internal tools; double Socket instances double-process events — source: youngju.dev guide.
- **Linear: verify HMAC, reply 200 fast.** `Linear-Signature` HMAC-SHA256 must be verified; respond <5s or webhook gets disabled; GraphQL 1500 complexity pts/hr — source: youngju.dev, @linear/sdk 4.x docs.
- **LLM JSON needs Zod safeParse + idempotency.** LLMs wrap JSON in chatter, drop fields; always safeParse with fallback, store event.id in KV, upsert by External ID in Notion — source: youngju.dev, codecanis.

## 2. Best Practices
- **ACP client pattern (authoritative: Zed/agent-client-protocol).** Spawn agent as subprocess with piped stdio, JSON-RPC 2.0, `initialize` handshake with protocolVersion, session lifecycle (new/load/resume/close), streaming `session/update` notifications. Official SDKs: `@agentclientprotocol/sdk` (TS, production), `agent-client-protocol` (Rust/Python). Custom agent config: `{command, args: ["acp"], env}`. Registry auto-updates from npm/PyPI/GitHub. Pin protocol version 1.
- **Cowork capability ordering (authoritative: claude.com/product/cowork, Anthropic Help Center).** Connectors/integrations first, browser second, screen/computer last resort. Direct integration is faster + more precise than pixels. Copy this ordering in k5-work tool selection.
- **Cowork packaging = plugins of skills+connectors+subagents.** File-based, installable, customizable per team; 11 open-source starter plugins; private marketplace for orgs — source: claude.com/blog/cowork-plugins 2026-01-30, Academy plugins course. k5-work should copy: `skills/` markdown playbooks + connectors + slash commands, not hardcoded tools.
- **Browser production pattern.** `max_steps` as billing rail, planner/executor model cascade (Sonnet/GPT-4o plan, Flash/mini act), DOM truncation (~4k tokens), prompt caching (>80% hits), storage-state persistence + recycle context every ~50 tasks (Chromium leaks), human-like movement (Bezier + Gaussian typing), Playwright traces retained on failure — source: aiworkflowlab, QASkills.sh 2026-07-07.
- **Office pure-JS stack for TS.** `docx@9.5.0` + `xlsx/SheetJS@0.18.5` + `pdf-lib@1.17.1` + `pptxgenjs@4.0.1`, zero native deps, works Node/browser/Workers — source: skills.sh/jezweb office, eliteai.tools. Always `await Packer.toBuffer()`, PDF y=0 is bottom-left, `type:'buffer'` for xlsx in Workers, base64 images for pptx in Workers (no `https` module), proper Content-Type/Disposition headers.
- **Integrations unified interface.** Single `BaseIntegration` (`testConnection/listChannels/fetchHistory/search`) normalizing to `IntegrationMessage`, per-platform rate limiting + exponential backoff (Slack 1000ms/Notion 300ms), never log tokens, secrets in env — source: CasperAI MULTI_PLATFORM_INTEGRATIONS.md, brownjer3/pipe (MCP server bridging GitHub/Slack/Jira/Linear/Notion). Better: expose via MCP layer so agent interface doesn't change when adding 5th tool — source: corsair.dev 2026-07-24.

## 3. Pitfalls & Language Quirks
- **TS ESM/CJS dual for pptxgenjs.** Needs Node 18+, bundler picks `dist/pptxgen.es.js`; Webpack/Docusaurus choke on `node:` prefix in `browser` field — needs ignore plugin — source: PptxGenJS integration docs. TS types incomplete (HAlign/AlignH export bugs, #902) — pin v4.0.1+, avoid reusing option objects.
- **Notion schema drift.** Users rename properties in UI; hardcoded `properties.Status.select.name` returns undefined and sync writes nulls everywhere. Must `databases.retrieve` at startup + interval, fail loudly (Slack alert + pause), never partial-write — source: codecanis.
- **Two-way Notion sync is nightmarish.** Eventual consistency + conflict resolution; pick one direction, other side read-only. Don't use Notion as customer-facing store; don't render arbitrary blocks without allow-list (8-10 types max).
- **ACP transport today = stdio only.** Remote agents need stable transport (open problem, Aug 2026). VS Code has no native ACP (Microsoft standardized on MCP) — community plugins only. Registry has no quality signals beyond "exists". Don't bet MVP on remote ACP or VS Code native.
- **Approval fatigue inverts safety.** Claude Code saw users blind-approve within weeks; mitigation was OS sandbox (Seatbelt/bubblewrap, 84% fewer prompts) — source: Anthropic containment post. k5-work web app can't rely on user reading bash; need AllowOnce/AllowThread/AllowAlways/Deny + auto-allow inside sandbox, human gate only for egress/destructive.
- **Chromium memory.** ~600MB resident per tab; 10 parallel sessions max on 16GB; pool + queue (Redis/SQS/Temporal), one task per pod, replace after — source: aiworkflowlab.

## 4. Differentiation
- **Industry standard (Cowork):** desktop-first (macOS/Windows) + sealed local VM + connectors-first + plugins + mobile/cloud handoff + enterprise RBAC/spend/OTEL. Strength: reaches local folders/apps web can't.
- **k5-work as pitched (web + TS + ACP):** runs anywhere, no install, model-agnostic via any ACP harness, open-source. Genuinely useful differences: (a) ACP наоборот — any harness plugs in, no lock-in (Cowork is Claude-only); (b) web delivery + Docker sandbox is easier for teams than per-laptop VM; (c) MCP-unified integrations mean adding 5th tool is zero agent-code change.
- **Vanity differences to avoid:** rebuilding agent loop when OpenCode/Pi/Codex already handle compaction/loop bugs; rebuilding browser-use loop when harness + CDP tool suffices; custom office XML when pure-JS libs exist.
- **Honest call:** follow standards for agent loop (delegate to ACP harness), browser (CDP tool + allowlist + evidence asserts), office (docx/xlsx/pptxgenjs), integrations (MCP layer + BaseIntegration). Differentiate on: ACP-harness-agnostic + web sandbox + plugins-as-files + permission UX for non-developers (Cowork's actual moat).

## Recommendation
Build thin client, not new agent: (1) TS web UI (chat + approvals + workspace/files) talking WS to server; (2) server spawns ACP harness via stdio (`@agentclientprotocol/sdk`), passes through tools the harness lacks (browser CDP, sandbox exec, office gen, MCP connectors); (3) sandbox = disposable Docker Linux+X11+VNC per session, egress allowlist, no long-lived creds; (4) office via pure-JS libs with Windows-PowerPoint test gate; (5) integrations behind MCP/unified interface with Zod-validated LLM glue, idempotency keys, schema-drift alerts. Start with 1 harness (OpenCode ACP), 1 sandbox image, 3 connectors (Slack/Notion/Linear), office create-only. Add Jira + plugins-as-files next.
